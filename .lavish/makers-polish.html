Give the page some punch.

More red. Better rhythm. A form that feels finished. Eight suggestions for the makers page, shown against the running version.

0 of 8 selectedReview your selection

Use the identity at full strength.

My recommendation is a red opening, a quieter transition into the application and a form that uses the desktop width. Fix the label rhythm and control states at the same time.

The colour comes from the existing palette. Marker Red carries the opening, actions and selection; the two cream tones separate reading from filling in answers.

Start with six.

M01, M03, M04, M05, M06 and M08.

M02 and M07 add more colour and density. The combined preview shows all eight so you can judge the stronger version.

These are review mockups. The public page has not been restyled. Selection applies to the makers page only.

M01

Bolder + colorize · Recommended

Give the opening a red poster treatment.

The current opening is all cream and left aligned. The back link also leaves a large gap before the headline.

The proposal. Use a single red block, a cream headline and a two-column composition. Bring the back link closer and keep the date and application action together.

The strongest visual change. The red belongs to the opening; the form stays on cream. Source

M02

Colorize · Optional

Give the process its own band.

Commitment and process currently blend into the same background as everything around them.

The proposal. Use the existing darker cream as a broad band. Red number blocks make the three real steps visible at a glance.

Optional extra colour. It makes the middle of the page denser; skip this if the red opening feels strong enough. Source

M03

Polish · Recommended

Make the pay answer a compact note.

A large section heading gives one short answer more space than it needs before the form.

The proposal. Keep the question and the volunteer answer, but put them together in a compact row. Stack them on mobile.

The answer remains explicit. This is a hierarchy and spacing change, with no change to the commitment. Source

M04

Bolder + layout · Recommended

Use the desktop width for the application.

The form currently occupies a narrow column at the left, leaving much of the desktop page empty.

The proposal. Put the application title, context and privacy note in a sticky left column, with the grouped form on the right. Stack the introduction above the form on mobile.

This is the main layout change. The form stays fully visible on one page, with its existing anchor and submission flow. Source

M05

Polish · Recommended

Keep labels together and pair short answers.

Required asterisks appear on their own lines. Name, email and language levels each consume a full row.

The proposal. Keep each label and its marker on one line. Pair name and email on desktop, align language levels in a row, and let long answers use the full form width.

Fields and requiredness stay the same. Name and email return to one column on mobile. Source

M06

Polish + colorize · Recommended

Make the fields look ready to use.

The pale fields and faint rules have little definition against the paper background. Short textareas also inherit the same minimum height as longer answers.

The proposal. Use a clear red outline, the existing 10px corner radius, a cream-light fill and an ink focus ring. Size short textareas for short answers.

A functional use of colour. Keep error copy in contrast-safe ink, with a visible border and text explanation. Source

M07

Colorize + interaction · Optional

Let choices show their selected state.

Ten theme choices and the practical checks currently read as a loose list of small checkboxes.

The proposal. Make the whole label a roomy target. Selected options use red and cream while keeping their native checkbox and tick visible.

Optional: this adds more visual weight to preferences. It changes presentation only, with no new options or defaults. Source

M08

Polish + interaction · Recommended

Finish with a clear send area.

The current square send button differs from the site's pill buttons, and the last action has little separation from the preceding fields.

The proposal. Give the required-field note and send action a darker-cream panel. Use the established pill shape, clear focus, a sending state and a readable error summary.

The preview shows the finish and selected practical checks. Sending, validation and receipt behaviour must be verified during implementation. Source

Evidence, scope and checks
  • Browser measurements record the current and proposed layouts at 1440px and 390px. Both proposals have zero horizontal overflow. This is a bounded design review, with no claim of measured conversion improvement.
  • DESIGN.md snapshot and colour and type tokens supplied the design direction. Existing fonts, two inks, cream surfaces and button shapes are retained.
  • Audience template, form and component CSS supplied the current behaviour and layout. Proposed screenshots use temporary DOM and CSS overrides.
  • Build concerns keep requiredness and mail operations open. These suggestions add no fields, promises, application steps or new brand colours.
  • Inputs, checkbox states and responsive layout are demonstrated. Full keyboard, validation, loading and receipt verification belongs to implementation of the selected changes.
