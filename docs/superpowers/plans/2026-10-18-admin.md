# Admin implementation plan

> **For agentic workers:** use superpowers:executing-plans or delegated tasks with explicit file ownership. Track checks below.

**Goal:** Build the Filament workspace for independent organisation review,
briefing refinement, maker selection, team matching and super-admin account management.

**Architecture:** Keep existing applications and immutable submitted answers.
Add operational fields, per-user reviews, edition-scoped teams and memberships.
Use Filament's defaults and session authentication; authorised organisers share
review/matching access, while account management is super-admin only.

**Tech stack:** Laravel 13, Livewire 4, Filament 5, existing SQLite/MySQL-compatible migrations.

**Spec:** `docs/wiki/build/30-admin-discovery.md`, supplemented by
`docs/raw/2026-10-18-admin-build-instruction.md`. The explicit build instruction
authorises proceeding now with routine choices recorded here, without another
design approval round. Already in the existing isolated Bloom worktree.

## Working decisions

- Navigation: Organisations, Makers, Teams, Admin accounts (super admin only),
  profile/password and login/reset. Save this sitemap in Notion as required.
- Shared skill vocabulary is the nineteen-label union from A-10/A-11:
  canonical Art direction and Content development / copywriting, plus PR,
  Service design, Back end development and Front end development. No free-form
  labels in the operational skill selectors; preserve original submitted text.
- Independent organisation ratings use a clear 1–5 scale with own comment.
  Show other assessments for consensus; absent reviews are excluded from averages.
  No automatic selection or communication follows a rating/status change.
- Organisation workflow includes status, contact notes, refined briefing and
  skills needed. Frederik's mailbox and manual message to Gwen stay external.
- Maker workflow includes status, submitted answers, operational main/backup
  skills and internal notes. No invented collective maker-rating requirement.
- Teams belong to an edition and one organisation application; each maker
  application belongs to at most one team. Selected/confirmed makers and
  organisations only; changes must respect audience, edition and uniqueness.
  Draft assignments are editable. No arbitrary team-size cap.
- All active admins can use these workflows; only super admins can manage
  accounts. No self-deactivation/demotion or removal of the last active super admin.
  Public users and deactivated accounts cannot access the panel or its actions.
- No Airtable import or automated selection email is implied by this build.
  Provision real accounts only with supplied emails; no guessed addresses or
  shared/default passwords. Provide a local setup command and private local
  reviewer access if emails are still pending.

## Review focus

- Cross-audience record IDs and tampered reviewer IDs must fail server-side.
- Conflicting or cross-edition team assignments must leave all data unchanged.
- Another organiser's review cannot be overwritten by a submitted user ID.
- Submitted HTML/URLs must not create script or unsafe-protocol links.
- An ordinary admin cannot promote users or disable the last usable super admin.
